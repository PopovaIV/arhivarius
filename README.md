# Семейный архив

Полная платформа для хранения генеалогических данных: документы, книги, фотографии, реестр людей, древо, чат, ссылки.

## Стек

- **PHP 8.3 + Symfony 7.1**
- **PostgreSQL 16** с FTS (tsvector + GIN), JSONB
- **Twig + Bootstrap 5**
- **PDF.js, epub.js** — встроенные читалки
- **d3.js** — визуализация генеалогического древа
- **poppler-utils, djvulibre** — экстракция текста и обложек
- **Long polling** для реалтайма чата
- **Docker Compose** для запуска

| 8 | Чат: общий канал + личные сообщения |

## Запуск

```bash
cd genarchive

docker compose run --rm php composer install
docker compose up -d --build
docker compose exec php bin/console doctrine:migrations:migrate -n
docker compose exec php bin/console app:create-admin
docker compose exec php mkdir -p var/uploads/{photos,books/covers,documents}

# http://localhost:8080
```

## Архитектурные заметки по Фазе 8 (чат)

### Почему long polling, а не WebSocket/Mercure

Long polling даёт ощущение реалтайма (новые сообщения появляются в течение ~25 сек или сразу как пришли) и работает за любым NAT/корпоративным фаерволом без отдельной инфраструктуры. Для семейного архива на 5-50 пользователей это идеально: никакого дополнительного процесса, никакой настройки HTTP/2 push, никаких проблем с прокси.

Если когда-нибудь захочется мгновенной доставки — Mercure-бандл уже подключен в `docker-compose.yml`. Достаточно добавить публикацию события в `ChatController::send()` и подписку через `EventSource` в JS.

### Direct-каналы через directKey

Личный диалог между Алисой (id=5) и Бобом (id=12) хранится с `direct_key = '5_12'` — отсортированная пара. Это даёт O(1) лукап без перебора участников: `findOneBy(['directKey' => '5_12'])`. Два запроса от обоих пользователей всегда найдут один и тот же канал.

UNIQUE-констрейнт на `direct_key` гарантирует, что параллельные запросы не создадут два канала на одну пару.

### Непрочитанное через ChatReadState

При открытии канала id последнего сообщения записывается в `chat_read_state.last_read_message_id`. Бейдж непрочитанного в сайдбаре = `COUNT(messages WHERE id > last_read_message_id)`. Простая и точная схема, не требует синхронизации статусов на каждое сообщение.

### Soft delete сообщений

Тоже soft, не физическое. Удалённое сообщение исчезает у всех, но в БД остаётся — потенциально нужно для модерации админу. Сейчас отдельной админской панели для чата нет, но можно дописать через тот же `SoftDeletableInterface` паттерн.

## Архитектурные заметки по Фазе 7 (ссылки)

Тривиальный CRUD с категориями. Единственная фишка — `groupedByCategory()` в репозитории возвращает ассоциативный массив `[category.value => Link[]]`, который Twig рендерит сразу как карточки по разделам. Поиск работает по названию, описанию и тегам через `LIKE %query%` — для нескольких сотен ссылок этого с запасом.
